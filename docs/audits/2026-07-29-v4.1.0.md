harness 自身在第一版有兩個缺陷，修掉後結果才可信：

- `execFileSync('npm.cmd', ...)` 在 Node 20+ 會 EINVAL（不能直接 spawn `.cmd`）→

> 教訓：驗證工具本身也會有假綠燈，而且它的假綠燈會偽裝成「全部通過」。

## 4. 測試套件變化

33 → **49 項**斷言。本輪新增涵蓋：暫時性 vs 結構性錯誤分類、注入機制自我檢查、
BOM、壞 JSON 不復活、陣列（讀取端與寫入端）、`updateUserConfig` 拒絕覆寫、
`__proto__`（真的送出去的那種）、每次操作只讀一次設定檔。

新增的自我檢查值得一提：**「讀取錯誤注入機制本身有效」**。
注入是靠換掉 `fs.readFileSync`，但 ESM 靜態 import 會在模組實體化時綁死該函式 ——
注入寫錯位置時不會報錯，只會「什麼都沒發生」而讓後續斷言全部假通過。
所以先斷言注入本身有效，再用它測別的。
